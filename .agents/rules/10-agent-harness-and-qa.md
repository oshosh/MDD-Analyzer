# 에이전트 하네스 및 QA 규칙

## 완료의 정의

에이전트의 설명이나 코드 변경만으로 작업을 완료 처리하지 않는다. 완료는 다음
세 가지가 연결될 때 성립한다.

1. **완료 조건**: 사용자가 관찰할 수 있는 동작과 변경하지 말아야 할 제약을
   명시한다.
2. **검증 방법**: 각 완료 조건을 확인하는 테스트, API 확인, 화면 흐름 또는
   수동 점검 방법을 정한다.
3. **실행 증적**: 실제로 실행한 명령과 통과·실패 결과를 작업 결과에 남긴다.

기획이 모호하면 구현을 시작하기 전에 완료 조건을 제안하고, 사용자의 선택이
필요한 제품 결정은 추측으로 확정하지 않는다.

## 변경 유형별 최소 검증

| 변경 유형 | 우선 검증 | 필요 시 추가 검증 |
| --- | --- | --- |
| 금융 계산·시계열·환율 | 결정적 단위 테스트, 경계값·결측값 | RAW 데이터 또는 기준 수치 비교 |
| API·데이터 정규화 | Zod 검증 및 Route Handler 테스트 | 실제 응답 형태를 고정한 통합 테스트 |
| 화면·사용자 흐름 | 타입 검사와 관련 컴포넌트 테스트 | Playwright E2E, 모바일 390px·414px 화면 확인 |
| 설정·에이전트 지침·도구 | 설정 구조 검사 | 해당 도구의 런타임 진단 또는 실제 로드 결과 |
| 리팩터링 | 기존 관련 테스트 | 동작 변경이 없음을 보이는 회귀 테스트 |

테스트가 없으면 "테스트 없음"으로 끝내지 않는다. 재현 가능한 테스트를 추가할지,
현재 자동화가 불가능한 이유와 대체 검증을 명확히 남긴다.

## 기획에서 구현으로 넘기는 계약

기획 문서 또는 작업 시작 메시지에는 아래 항목을 짧게 정리한다.

- 사용자 시나리오와 성공 조건
- 입력·출력·오류 상태 및 데이터의 기준 원본
- 변경 범위와 유지해야 하는 불변 조건
- 완료 조건별 검증 계층과 실행 명령

검증 설계가 구현을 복제하는 수준의 단순한 테스트가 되지 않게 한다. 계산은 독립된
기대값과 경계값으로, UI는 사용자가 수행하는 핵심 흐름과 관찰 가능한 결과로
검증한다.

## 실행과 보고

변경 후에는 영향 범위에 맞는 검증을 실행한다. 기본 품질 게이트는
`pnpm run verify`이며, 여기에는 에이전트 지침 주입 검사, 타입 검사, 단위 테스트가
포함된다. E2E가 필요한 변경에는 이 명령만으로 충분하지 않으며 별도의 Playwright
증적을 추가한다.

최종 보고에는 다음을 포함한다.

- 변경된 사용자 동작 또는 불변 조건
- 실행한 검증 명령과 결과
- 실행하지 못한 검증, 그 이유, 남은 위험

외부 API, 실시간 시세, 브라우저·인증 환경처럼 통제하지 못한 요소는 고정된
fixture 또는 mock을 사용해 결정적 테스트를 먼저 만들고, 별도 통합 검증에서 실제
의존성을 확인한다.
